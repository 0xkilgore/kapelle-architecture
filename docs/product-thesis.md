# Product thesis

## Agents as a software medium

The most important product question is not whether agents can perform useful work. They already can. The question is how people will live with many of them.

Kapelle assumes that agents will become a software medium in their own right. A person may use a career agent, travel agent, finance agent, neighborhood agent, research agent, or a narrow utility supplied by a bank or service provider. Some will run continuously. Others will be used a few times a year.

The interface cannot be only a list of chat sessions. Once work becomes asynchronous, recurring, and distributed, the operator needs a stable place to understand the system.

## Individual productivity first

Kapelle is not initially a company-in-a-box product. It starts with one person working across many domains.

This choice affects the product:

- projects can mix professional and personal contexts;
- the fleet contains both reusable specialists and project-specific agents;
- local files and local services remain important;
- privacy and user control matter before enterprise administration;
- the interface must help a person, not merely report infrastructure metrics.

Collaboration and organizational agents can follow, but the first product should be valuable before a team administrator exists.

## The operator loop

The primary loop is:

1. Work enters through chat, email, voice, schedules, files, or another agent.
2. The system converts intent into durable tasks and dispatches.
3. Agents and deterministic tools execute.
4. Outputs land as artifacts with evidence and provenance.
5. Kapelle ranks what matters and asks for human input only when necessary.
6. Feedback becomes another durable operation or task.
7. The system continues without requiring the human to reconstruct context from chat.

## Product differentiation

Kapelle is differentiated by two connected choices.

### An operator cockpit, not a chat wrapper

The interface is built around attention, state, and review. Chat remains available, but the routine operating surface is scan-first.

### A document-centered substrate

Artifacts, tasks, dispatches, health, and other important state become typed documents with operation histories. The same canonical state can support a human-readable page, an indexed query, an agent context, and a verification trail.

## Economic direction

The product should be neutral across model providers and hostile to unnecessary token use.

The durable value is not generic model hosting. A stronger long-term model is an open agent ecosystem with paid service capabilities. An agent might be free when operating on uploaded files and charge for a hosted data connection, specialized integration, or continuously managed service.

Kapelle can become the neutral interface through which those agents and services are discovered, operated, and trusted.
